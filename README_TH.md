# BPE Paper Server (รันบน Railway)

ฝั่ง Cloud ของระบบ: รับแท่งราคา M5 สร้างสัญญาณตามกฎ BPE (ICT) เก็บคิวสัญญาณ ให้ ESP32 มาอ่านไปตัดสินใจ แล้วถือพอร์ตทดลอง (Paper) จำลองการเข้า-ออกไม้ มี Dashboard และแจ้งเตือน LINE

```
แหล่งราคา M5 (MT4 / TradingView / อื่นๆ) --> /tv  (แท่งราคา)
                                       |  ตัวสร้างสัญญาณ BPE บนเซิร์ฟเวอร์
                                       |
ESP32 (เทรดเดอร์) <--อ่านสัญญาณ-- Railway --> Dashboard / LINE
        '--ส่งคำสั่งเปิด/ปิดไม้---->  พอร์ต Paper (fill ด้วยแท่งราคา M5 ที่ส่งเข้ามา)
```

- ไม่มีไลบรารีเพิ่ม ไม่ต้อง `npm install`
- ต้องใช้ Node 18 ขึ้นไป (Railway ใช้ให้เอง)

## Deploy บน Railway
1. สร้างโปรเจกต์ใหม่ที่ Railway แล้วนำโฟลเดอร์นี้ขึ้น (GitHub repo หรือ `railway up`)
2. แท็บ **Variables**
   | ตัวแปร | ความหมาย |
   |---|---|
   | `API_KEY` | **จำเป็น** รหัสลับอย่างน้อย 12 ตัวอักษร ตั้งเองแล้วใช้ค่าเดียวกันใน `config.h` ของ ESP32 และใน URL ของ Webhook |
   | `START_BALANCE` | เงินเริ่มต้นของพอร์ตทดลอง (ค่าเริ่มต้น 10000) |
   | `SYMBOL` | ชื่อสัญลักษณ์ที่แสดง (ค่าเริ่มต้น US100) |
   | `DIGITS` | ทศนิยมของราคา (ค่าเริ่มต้น 2) |
   | `MULTIPLIER` | มูลค่าเงินต่อ 1 จุดราคาต่อ 1.00 หน่วย: CFD ดัชนี = 1 (ค่าเริ่มต้น), MNQ = 2, NQ = 20 |
   | `SPREAD` | สเปรดเป็นหน่วยราคา เช่น 1.0 (ค่าเริ่มต้น 0) ใช้ตอน fill และเช็ก SL ของไม้ Sell |
   | `MIN_VOLUME`, `STEP_VOLUME`, `MAX_VOLUME` | ขนาดไม้ในหน่วย 0.01 (ค่าเริ่มต้น 1 / 1 / 1000000) |
   | `DATA_DIR` | `/data` เมื่อติดตั้ง Volume (ข้อ 3) |
   | `LINE_CHANNEL_TOKEN`, `LINE_TO` | แจ้งเตือน LINE (ดูด้านล่าง) |
   | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `NOTIFY_WEBHOOK_URL` | ไม่บังคับ |
3. **สำคัญ:** เพิ่ม **Volume** ที่ Mount path `/data` (และตั้ง `DATA_DIR=/data`) ไม่เช่นนั้นข้อมูลพอร์ตหายทุกครั้งที่ deploy ใหม่
4. **Settings → Networking → Generate Domain** จะได้ `https://xxxx.up.railway.app`
5. เปิด URL นั้นในเบราว์เซอร์ ใส่ API Key เพื่อดู Dashboard (เช็กว่าเซิร์ฟเวอร์ทำงานที่ `/health`)

## ป้อนราคา M5 ให้เซิร์ฟเวอร์ (ไม่ต้องใช้ TradingView)
ตัวสร้างสัญญาณ BPE รันอยู่บนเซิร์ฟเวอร์นี้เลย (`lib/bpe.js` แปลงจากตรรกะ EA v1.30) ทุกครั้งที่แท่ง M5 ปิด เซิร์ฟเวอร์จะเช็กเงื่อนไข (ทิศทาง H4/D1 → โซน POI M15 → กวาดสภาพคล่อง → displacement → FVG) แล้วออกสัญญาณให้ ESP32 ตัดสินใจ ต้องมีแหล่งแท่ง M5 ที่ปิดแล้ว เลือกได้ 1 ทาง

**ทาง ก: ให้เซิร์ฟเวอร์ดึงจากเว็บฟรีเอง (แนะนำสำหรับ Forward Test)**
ตั้งตัวแปรใน Railway แล้วไม่ต้องทำอย่างอื่น
| ตัวแปร | ค่า |
|---|---|
| `FEED` | `yahoo` (ไม่ต้องมี key) หรือ `twelvedata` |
| `FEED_SYMBOL` | `NQ=F` (ค่าเริ่มต้นของ yahoo, ฟิวเจอร์ส Nasdaq 100 เกือบ 24 ชม.) หรือ `QQQ` (twelvedata) |
| `FEED_KEY` | key ฟรีของ Twelve Data (เฉพาะ twelvedata) |
| `FEED_WARMUP_DAYS` | จำนวนวันที่ดึงมาเป็นข้อมูลอุ่นเครื่องครั้งแรก (ค่าเริ่มต้น 30 สูงสุด 59) |
วิธีทำงาน: เซิร์ฟเวอร์ดึงแท่ง M5 ทุกครั้งหลังแท่งปิด (ราว 5 วินาที) ครั้งแรกที่เริ่มทำงาน แท่งที่ดึงมาใช้เป็น "ข้อมูลอุ่นเครื่อง" สำหรับหาทิศทาง H4/D1 เท่านั้น ไม่มีการเทรดและไม่นับผล ตั้งแต่นั้นเป็นต้นไปทุกแท่งที่ปิดคือ Forward จริง ถ้าเซิร์ฟเวอร์หยุดไปนาน แท่งที่ตกหล่นจะถูกเติมเข้ามาเพื่อให้ SL/TP ถูกเช็ก แต่ไม่ออกสัญญาณย้อนหลัง สถานะแหล่งราคาแสดงในการ์ด BPE บน Dashboard
**ข้อควรรู้ (ผมเรียกเว็บเหล่านี้จากที่นี่ไม่ได้ จึงยังไม่ได้ทดสอบกับเว็บจริง ทดสอบด้วยเซิร์ฟเวอร์จำลองที่ตอบรูปแบบเดียวกันเท่านั้น):**
- Yahoo เป็น endpoint ที่ไม่เป็นทางการ อาจช้ากว่าตลาดจริง ถูกจำกัดหรือบล็อก IP ของคลาวด์ หรือเปลี่ยนรูปแบบเมื่อไหร่ก็ได้ ถ้า Dashboard ขึ้นข้อผิดพลาดตรงช่อง "แหล่งราคา" ให้ส่งข้อความมาให้ผมดู
- Twelve Data แพ็กเกจฟรี (Basic) จำกัด 8 คำขอต่อนาที และ 800 ต่อวัน หน้าราคาของเขาระบุว่าครอบคลุมหุ้นสหรัฐ ฟอเร็กซ์ และคริปโต ไม่ได้ระบุดัชนีหรือฟิวเจอร์ส จึงใช้ `QQQ` (ETF) แทน แต่ราคาและเวลาเทรดต่างจาก US100 (ไม่มีช่วงกลางคืน จึงขาดระดับ Asia/London และ PDH) สัญญาณจึงต่างจากที่ทดสอบไว้ และต้องปรับ `SPREAD` / `MULTIPLIER` ให้เหมาะกับราคา ETF
- ฟิวเจอร์ส NQ ราคาใกล้เคียง US100 ของโบรกเกอร์แต่ไม่เท่ากัน (ส่วนต่างฟิวเจอร์ส/เงินสด) ผลที่ได้ใช้ประเมินกลยุทธ์ ไม่ใช่ผลเทรดจริงที่โบรกเกอร์

**ทาง ข: MT4 ส่งแท่งให้ (ฟรี ราคาตรงกับโบรกเกอร์)**
1. เปิด `tools/ChartDesk_BarPush.mq4` ใน MetaEditor แก้ `ServerUrl` และ `ApiKey` แล้วคอมไพล์
2. ใน MT4: Tools → Options → Expert Advisors ติ๊ก Allow WebRequest แล้วเพิ่ม URL ของ Railway
3. ลาก EA ไปที่ชาร์ต M5 ของสัญลักษณ์ที่เทรด (เช่น US100) ต้องเปิด MT4 ทิ้งไว้ (VPS หรือเครื่องที่เปิดตลอด)
4. EA ตัวนี้ผมยังไม่ได้ทดสอบใน MT4 จริง ถ้ามี error ส่งมาให้แก้

**ทาง ค: TradingView Webhook (ต้องใช้แพ็กเกจเสียเงิน)**
ส่ง `{"event":"bar","t":<epoch วินาที UTC>,"o":..,"h":..,"l":..,"c":..}` เข้า `POST /tv?key=API_KEY` ทุกครั้งที่แท่งปิด (สคริปต์ `tradingview/ChartDesk3L.pine` ส่งให้ได้ แต่สัญญาณจากสคริปต์นั้นเป็นคนละกลยุทธ์กับ BPE ถ้าจะใช้เฉพาะแท่งราคา ให้ตั้งปิดสัญญาณของสคริปต์หรือใช้ Alert ส่งแท่งอย่างเดียว) ถ้าเป็นเวลาเซิร์ฟเวอร์ของโบรกเกอร์ใส่ `"serverTime":true`

**ทาง ง: เขียนตัวส่งเอง** ส่งแท่งเข้า `/tv` ด้วยรูปแบบเดียวกัน

**อุ่นเครื่อง (สำหรับทาง ข ค ง)** ตัวสร้างสัญญาณใช้ H4 และ D1 หาทิศทาง ต้องมีแท่งอย่างน้อย 12 วัน (แนะนำ 120 วัน) ไม่งั้นทิศทางเป็น "none" และไม่มีสัญญาณ (ทาง ก ทำให้เองตอนเริ่ม) นำเข้าได้จากไฟล์ M5 จาก MT4 (`ChartDesk_ExportBars.mq4` หรือ History Center) แล้วรัน:
```
node tools/upload_history.js US100_M5.csv https://xxxx.up.railway.app API_KEY
```
(เวลาในไฟล์ถือเป็นเวลาเซิร์ฟเวอร์ของโบรกเกอร์ ถ้าเป็น UTC เพิ่ม `--utc`) ดูผลที่การ์ด "ตัวสร้างสัญญาณ (BPE)" บน Dashboard

**ตัวแปรเพิ่มเติม (ไม่บังคับ)** `BPE_ENABLED=0` ปิดตัวสร้างสัญญาณ (รับจาก TradingView อย่างเดียว) · `BPE_RISK_PERCENT` (2) · `BPE_MAX_TRADES` (3) · `BPE_DAILY_LOSS` (10) ใช้ตรวจเงื่อนไขในตัวสร้างสัญญาณ เหมือน EA เดิม · `BPE_CONFIG` ใส่ JSON เพื่อแก้พารามิเตอร์อื่น เช่น `{"setups":["M1","M3"]}` (โหมดเดิม: `{"setupMode":"legacy","model":2,"dispMode":0}`)

**ความแม่นยำ:** ทดสอบกับราคา M5 จริงของ US100 (ราว 62,000 แท่ง) ตรรกะบน JavaScript ได้ออเดอร์ตรงกับ C++ เดิมทุกบรรทัด (35 ออเดอร์) และผ่านเซิร์ฟเวอร์ครบวงจร 32 จาก 32 ออเดอร์แบบ limit ตรงกัน ส่วนแบบ market ราคาเข้าอ้างอิงต่างจากชุดทดสอบเดิมเล็กน้อย (ใช้ราคาปิดแท่งล่าสุดแทนราคาเปิดแท่งถัดไป) **นี่คือการทดสอบว่าโค้ดทำงานเหมือนเดิม ไม่ได้แปลว่ากลยุทธ์ทำกำไรได้จริง**

## ตั้งแจ้งเตือน LINE
LINE Notify ปิดบริการไปแล้ว ต้องใช้ **LINE Messaging API**
1. เข้า https://developers.line.biz สร้าง Provider และ Channel ชนิด **Messaging API**
2. แท็บ **Messaging API** ออก **Channel access token (long-lived)** ใส่ตัวแปร `LINE_CHANNEL_TOKEN`
3. แท็บ **Basic settings** คัดลอก **Your user ID** (ขึ้นต้นด้วย U) ใส่ `LINE_TO` แล้วสแกน QR เพิ่มบอทเป็นเพื่อน (ไม่เพิ่มเพื่อน ข้อความจะไม่เข้า)
4. ทดสอบ: `curl -X POST https://xxxx.up.railway.app/api/notify-test -H "x-api-key: API_KEY"`

ข้อความที่แจ้ง: สัญญาณที่ได้รับ, ESP32 รับหรือข้าม (พร้อมเหตุผล), วาง/ยกเลิก limit, เปิดไม้, ปิดไม้พร้อมกำไร/ขาดทุน ข้อความในคำขอเดียวกันถูกรวมเป็น push เดียวเพื่อประหยัดโควตา push message นับโควตารายเดือนของ LINE Official Account ซึ่งต่างกันตามประเทศ/แพ็กเกจ ตรวจในบัญชีของคุณ

### แจ้งสถานะทางไลน์ (เพิ่มใหม่)
| ข้อความ | เมื่อไหร่ | ปิด/ปรับด้วย |
|---|---|---|
| 👀 setup ที่รออยู่ | เมื่อ setup เดินถึงขั้นที่กำหนด (ครั้งเดียวต่อขั้น) พร้อมจุดเข้าที่คาด/SL/TP/RR (ประมาณการ) | `LINE_STATUS_SETUP_STAGE` (ค่าเริ่มต้น `3` = ยืนยันกลับตัวแล้วรอ FVG, `2` = ถี่ขึ้นตั้งแต่กวาดแล้ว, `0` = ปิด) |
| 📊 สรุปวัน | ตอนข้ามวัน (17:00 เวลานิวยอร์ก) ถ้าวันนั้นมีไม้/สัญญาณ/setup (วันเงียบไม่ส่ง) | `LINE_STATUS_DAILY=0` ปิด |
| ⚠️ ฟีดราคาไม่เข้า / ✅ กลับมาแล้ว | ฟีดล้มเหลวต่อเนื่องเกิน 15 นาที (เช่น Yahoo บล็อก) ตลาดปิดไม่ถือว่าล้มเหลว | `LINE_STATUS_FEED=0` ปิด |
| 📋 สถานะตามสั่ง | พิมพ์ **สถานะ** ในแชตกับบอท | ต้องตั้ง `LINE_CHANNEL_SECRET` และ Webhook (ด้านล่าง) |

ข้อความตามคำสั่ง "สถานะ" เป็น **reply** ซึ่งไม่นับโควตา push จึงถามกี่ครั้งก็ได้ แต่ข้อความอัตโนมัติด้านบนเป็น push ถ้าแผนของคุณมีโควตาต่ำ ให้คง `LINE_STATUS_SETUP_STAGE=3` หรือปิดข้อความที่ไม่ต้องการ

ตั้งคำสั่ง "สถานะ":
1. LINE Developers → Channel ของคุณ → แท็บ **Basic settings** คัดลอก **Channel secret** ใส่ตัวแปร `LINE_CHANNEL_SECRET` ใน Railway (อย่าวางในแชต/GitHub)
2. แท็บ **Messaging API** → **Webhook URL** ใส่ `https://xxxx.up.railway.app/line/webhook` → กด **Verify** → เปิด **Use webhook**
3. แท็บเดียวกัน ปิด **Auto-reply messages** (ไม่งั้นบอทจะตอบข้อความอัตโนมัติของ LINE ซ้อนกัน)
4. พิมพ์ "สถานะ" ในแชตกับบอท จะได้ยอดเงิน ไม้ที่เปิด และทิศทาง/ช่วงเทรด/setup ของทุกสินทรัพย์ (ตอบเฉพาะบัญชีที่ตรงกับ `LINE_TO`)
- ทดสอบโดยไม่ใช้แชต: `GET /api/status-text` (ดูข้อความ) หรือ `POST /api/notify-status` (ส่งเป็น push หนึ่งครั้ง)

## API (ต้องมี header `x-api-key`)
`GET /api/meta` · `GET /api/signals?after=<id>` · `POST /api/signals/ack` · `POST /api/order` · `POST /api/cancel` · `POST /api/close` · `POST /api/amend` · `GET /api/state` · `GET /api/stats` · `GET /api/trades` · `POST /api/reset` (ล้างพอร์ตเริ่มใหม่ ส่ง `{"balance":5000}` เพื่อเปลี่ยนเงินเริ่มต้น)

## ข้อจำกัด
- เป็นการจำลอง ไม่ใช่โบรกเกอร์จริง: ไม่มี slippage, swap, คอมมิชชัน, มาร์จิ้น ผลจริงจะแย่กว่าเล็กน้อย
- การ fill ใช้แท่งราคาที่ส่งเข้ามา ถ้าแท่งตกหล่นหรือช้า ผลจำลองและสัญญาณจะคลาด (ถ้าแท่งขาดหาย ตัวสร้างสัญญาณจะอ่านราคาต่อเนื่องข้ามช่องว่าง) Dashboard แสดงอายุของแท่งล่าสุด ถ้าเกิน 15 นาที ESP32 จะไม่รับสัญญาณใหม่
- ถ้า ESP32 ออฟไลน์ สัญญาณเข้าสะสมในคิว พอกลับมา สัญญาณเข้าไม้ที่เก่ากว่า 10 นาทีจะถูกข้าม ส่วนไม้ที่เปิดอยู่ยังถูกเช็ก SL/TP ที่เซิร์ฟเวอร์ตามปกติ แต่การปิดไม้ตอนจบ Killzone เป็นหน้าที่ของ ESP32
- เซิร์ฟเวอร์เก็บสัญญาณล่าสุด 500 รายการ

## บันทึกเหตุผลของแต่ละไม้ (ทำไมเข้า / ทำไมออก)

ทุกไม้ที่มาจากเครื่องยนต์ BPE จะเก็บ 2 อย่างติดไปกับไม้นั้นจนปิด:

- **ทำไมถึงเข้า** (`why`): Bias H4/D1, โซน POI ที่ราคาเข้า, สภาพคล่องที่ถูกกวาด (ชื่อ+ราคา), MSS/CISD ที่ยืนยัน, โมเดล (Turtle Soup/Unicorn) และโซนเข้า, SL อิงอะไร, TP คือสภาพคล่องไหน (เป้าหมายที่เท่าไร), RR, และลำดับเหตุการณ์ของ setup นั้น
- **ทำไมถึงออก** (`exitWhy`): TP/SL/เวลา พร้อม MFE/MAE (ราคาไปทางที่ถูก/สวนสูงสุดกี่ R), จำนวนแท่งที่ถือ, และสำหรับ SL จะบอกว่าโดนเร็วไหม เคยบวกแล้วกลับไหม ราคาหลุดโซน POI หรือแค่โดนกวาด

ดูได้ที่: Dashboard → ตาราง "ไม้ที่ปิดแล้ว" กดเลขไม้ / ข้อความ LINE ตอนเปิดและปิดไม้ / `GET /api/trades` (ฟิลด์ `why`, `exitWhy`, `mfeR`, `maeR`, `bars`)

หมายเหตุ: ข้อความ "ทำไมออก" เป็นการวิเคราะห์อัตโนมัติจากราคาหลังเข้า ไม่ใช่ข้อสรุปว่าเหตุผลจริงคืออะไร และแท่งที่โดน SL จะไม่ถูกนับ MFE (ใช้กติกา stop-first เดียวกับ paper engine)

## หลายสินทรัพย์ (US100, US30, US500, EURUSD, GBPUSD, AUDUSD, USDCAD, USDJPY, XAUUSD, XAGUSD)

ตั้งตัวแปรเดียวใน Railway: `SYMBOLS=US100,US30,US500,EURUSD,GBPUSD,AUDUSD,USDCAD,USDJPY,XAUUSD,XAGUSD` (ลบหรือไม่ใส่ `SYMBOLS` = โหมดเดิมสินทรัพย์เดียวตาม `SYMBOL`)

- **บัญชี paper เดียว** ยอดเงินและ ID ร่วมกัน แต่แต่ละสินทรัพย์มีแท่งราคา เครื่องยนต์ BPE และฟีดของตัวเอง ราคาดึงจากเว็บฟรีตามชื่อ (Yahoo: `NQ=F`, `YM=F`, `EURUSD=X`, `JPY=X`, `GC=F`)
- **ช่วงเวลาเทรด (killzone) ตามสินทรัพย์:** US100/US30 = NY AM+PM · EURUSD = London + NY AM (เริ่ม 08:30 NY) · USDJPY = Asia + NY AM · XAUUSD = London + NY AM ทำให้มีหน้าเทรดเกือบทั้งวัน แต่ไม่ได้แปลว่าเทรดตลอด 24 ชม. และปิดเสาร์-อาทิตย์
- **สเปรด/มูลค่าต่อ lot** ใส่ค่าทั่วไปให้แล้ว (EURUSD 1.2 pip, USDJPY 1.2 pip, ทอง 0.30, US30 2.0, US100 1.0) ปรับได้ด้วย `SPREAD_EURUSD=0.00015`, `MULT_XAUUSD=100`, `FEED_SYMBOL_XAUUSD=XAUUSD=X` ฯลฯ และตั้งค่า BPE เฉพาะตัวด้วย `BPE_CONFIG_EURUSD={"minRR":2.5}`
- **เพิ่มใหม่:** US500 (Yahoo `ES=F`, killzone NY AM+PM) · GBPUSD (`GBPUSD=X`, London + NY AM) · AUDUSD (`AUDUSD=X`, Asia + NY AM) · USDCAD (`CAD=X`, NY AM) · XAGUSD เงิน (`SI=F`, London + NY AM) สเปรดเป็นค่าประมาณทั่วไป ปรับได้ด้วย `SPREAD_<คู่>`
- ฟีดฟรีมีเพดานการเรียก ถ้าใช้ Twelve Data (ฟรี 8 ครั้ง/นาที, 800 ครั้ง/วัน) ไม่ควรเปิดทั้ง 10 ตัว แนะนำ Yahoo
- USDJPY และ USDCAD: กำไรเป็นเงินเยน/ดอลลาร์แคนาดา ระบบแปลงเป็นดอลลาร์ด้วยราคาปัจจุบันของแท่งล่าสุด (ประมาณการ)
- **ความเสี่ยงรวม:** ความเสี่ยง 2% ต่อไม้ยังเท่าเดิม แต่มีตัวคุม `BPE_MAX_OPEN` (ค่าเริ่มต้น 3 = เปิด/รอพร้อมกันรวมทุกสินทรัพย์ไม่เกิน 3) และ `BPE_DAILY_LOSS` (ขาดทุนรายวันรวมทุกสินทรัพย์) ไม้ต่อสินทรัพย์ต่อวัน `BPE_MAX_TRADES` (3) ระวัง EURUSD กับ USDJPY (และทอง) เคลื่อนไหวตามดอลลาร์ ไม้อาจชนะ/แพ้พร้อมกัน
- **Twelve Data (ฟรี)** ใช้ได้กับ EUR/USD, USD/JPY, XAU/USD ส่วนดัชนีใช้ ETF แทน (QQQ, DIA) แนะนำ Yahoo ก่อน เพราะได้ดัชนีฟิวเจอร์สจริง
- API เพิ่ม `sym`: `/api/meta?sym=EURUSD`, `/api/bpe?sym=`, `/api/trades?sym=`, `/api/signals?sym=`, `POST /api/order {sym,...}` และ `POST /api/history {sym,...}` (ไม่ใส่ = สินทรัพย์แรก)
- Dashboard: ตาราง "ทุกสินทรัพย์", แท็บเลือกสินทรัพย์, คอลัมน์สินทรัพย์ในทุกตาราง, สถิติแยกตามสินทรัพย์ใน `/api/stats` (`bySymbol`)

ข้อควรรู้: การเพิ่มสินทรัพย์เพิ่มจำนวนสัญญาณ ไม่ได้เพิ่มความได้เปรียบ กลยุทธ์ BPE ยังไม่เคยพิสูจน์ว่ามี edge บน FX/ทอง (ทดสอบย้อนหลังไว้เฉพาะ US100) Forward Test ชุดนี้จึงเป็นการวัดว่าแต่ละสินทรัพย์ได้ผลจริงหรือไม่ ควรดูสถิติแยกรายสินทรัพย์ก่อนเพิ่มความเสี่ยง


## โมเดลเข้าเทรด 4 แบบตามหนังสือ BPE (Trade Setup 2022 & Unicorn, หน้า 577–586)

ตัวสร้างสัญญาณใช้โหมด `classic` เป็นค่าเริ่มต้น ทุกไม้ติดป้ายโมเดลไว้ในคอมเมนต์ (`BPE M3`) ในเหตุผล "ทำไมถึงเข้า" (เช็กลิสต์ตามหนังสือ) และในสถิติแยกโมเดลบนหน้าเว็บ

| ป้าย | เงื่อนไขตามหนังสือ | จุดเข้า |
|---|---|---|
| **M1** | HTF POI → กวาด SSL/BSL → MSS → FVG ในโซน Discount (ขาซื้อ) หรือ Premium (ขาขาย) → R:R > 1:2 | ขอบ FVG |
| **M2** | M1 + IDM (swing ย่อยหลัง MSS ที่อยู่นอก FVG ถูกกวาดก่อนราคาลงมาที่ FVG) | ขอบ FVG |
| **M3** | M1 + FVG ซ้อนกับ OTE 62–79% ของช่วงจากจุดกวาดถึงจุดสุดท้าย | ส่วนที่ FVG ซ้อน OTE |
| **M4 BOX** | กรอบ consolidation ก่อนหน้า → กวาดขอบกรอบ (equal low/high) ที่ HTF POI → ปิดเบรกกลับเข้ากรอบ → รอ retest | 50% ของกรอบ SL เลยจุดที่กวาด |
| **UC** | Unicorn: FVG ซ้อน Breaker Block | ส่วนที่ซ้อนกัน |

- ระบบใช้ **MSS** ยืนยัน (ตามหนังสือ) ไม่ใช้ CISD ในโหมดนี้
- ใครครบเงื่อนไขก่อนก็เข้าก่อน ป้ายที่ติดคือโมเดลที่มีเงื่อนไขเสริมครบที่สุดตอนเข้า: UC > M3 > M2 > M1
- M2 และ M3 เป็น M1 ที่มีเงื่อนไขเพิ่ม จึงใช้เป็นป้ายสำหรับเทียบสถิติ ถ้าต้องการให้รอเฉพาะ IDM ให้ตั้ง `{"setups":["M2"]}`
- เลือกโมเดลที่เปิดใช้: `BPE_CONFIG` เช่น `{"setups":["M1","M3","M4"]}` ค่าเริ่มต้นคือเปิดทั้งหมด `["M1","M2","M3","M4","UC"]`
- กลับไปใช้ Turtle Soup / Unicorn แบบเดิม (CISD): `{"setupMode":"legacy"}`
- ค่าปรับของ M3/M4: `oteLo` `oteHi` (0.62/0.79), `boxMinBars` `boxMaxBars` `boxMaxK` `boxEqK`
- ทดสอบย้อนหลังด้วยไฟล์ M5 ที่ export จาก MT4: `node tools/replay_models.js ไฟล์.csv '{}'` (แสดงสัญญาณและผลแยกตามโมเดล ใช้เช็กว่าโค้ดทำงาน ไม่ใช่พิสูจน์ว่ากลยุทธ์ได้กำไร)


## จุดเข้าของ setup ที่กำลังรอ (กราฟบน Dashboard)

กราฟราคามีแถบสรุปด้านบนบอกว่า setup ของสินทรัพย์นั้นอยู่ขั้นไหน และเส้นประบนกราฟคือจุดที่ setup รออยู่ **ไม่ใช่คำสั่งจริง**:

| ขั้น | สิ่งที่แสดง | จุดเข้า |
|---|---|---|
| 1/4 ราคาเข้า POI รอกวาด | POI ที่ราคาอยู่ + ระดับสภาพคล่องที่รอให้ถูกกวาด | ยังประเมินไม่ได้ |
| 2/4 กวาดแล้ว รอ MSS | จุดที่กวาด, เส้น MSS ที่ต้องปิดทะลุ, เส้น 50% (ใต้ = Discount), โซน OTE 62–79% | **ประมาณการ** ที่ขอบ OTE |
| 3/4 รอ FVG | เหมือนขั้น 2 | ประมาณการ |
| 4/4 FVG เกิดแล้ว | โซนเข้า + โมเดล (M1–M4/UC) | **จุดเข้าจริง** ถ้าโมเดลครบเงื่อนไข (รอเข้าช่วงเทรดถ้ายังไม่ถึง) |
| Model 4 | กรอบ BOX ที่เจอ | 50% ของกรอบ |

SL/TP/RR ที่แสดงคำนวณด้วยกฎเดียวกับตอนส่งคำสั่งจริง แต่ขั้น 2–3 ใช้ SL ที่จุดกวาด (กว้างกว่าจริง) จึงเป็นการประมาณแบบระวัง ถ้า RR ต่ำกว่าเกณฑ์ จะมีป้ายเตือนว่าถ้าไม่ดีขึ้นจะไม่เข้า ข้อมูลนี้อ่านอย่างเดียว ไม่มีผลต่อการส่งสัญญาณ (`/api/chart` ฟิลด์ `setup`)

## เกรดไม้ (A/B/C) และ bias ของทองคำ
- **เกรดเป็นแค่ป้าย ไม่กรองไม้** (comment ของออเดอร์: `BPE M1 GA`)
  - A = D1 เห็นด้วยกับทิศ **และ** มี confluence เพิ่ม (IDM ถูกกวาด / OTE ซ้อน / Unicorn)
  - B = ได้อย่างใดอย่างหนึ่ง · C = ไม่ได้ทั้งสองอย่าง (เช่น H4 ขัดกับ D1, M1/M4 ธรรมดา)
  - หน้า dashboard ส่วนสถิติจะแสดงผลแยกเกรด เพื่อดูว่ากลุ่มไหนคุ้มจริง
- **XAUUSD ใช้ `biasMode: 0` (H4 อย่างเดียว)** เพราะ H4 กับ D1 ขัดกันบ่อยจนไม่มีไม้ ไม้ที่ได้ส่วนใหญ่จะเป็นเกรด B/C
  - เปลี่ยนเองได้ด้วยตัวแปร `BPE_CONFIG_XAUUSD={"biasMode":1}`


## โหมดสอบ (กติกาแบบ Topstep) — `EXAM=1`

ทำให้เซิร์ฟเวอร์ตัวหนึ่งเป็น "บัญชีสอบ" ใช้ **สัญญา Micro futures** ราคา Yahoo เป็นฟิวเจอร์สอยู่แล้ว (`NQ=F`, `ES=F`, `GC=F` ...) และบังคับกฎสอบฝั่งเซิร์ฟเวอร์ ไม่ว่า ESP32 จะส่งคำสั่งอะไรมา ตั้ง **เป็นเซอร์วิส Railway แยก** (มี volume และ `API_KEY` ของตัวเอง) เพื่อไม่ปนกับบัญชีทดสอบเดิม

ค่าตั้งต้นคือบัญชี 50K ตามกฎที่เผยแพร่ ณ ต.ค. 2026 **ตรวจกับ Topstep ก่อนใช้จริงเสมอ กฎและตัวเลขเปลี่ยนได้** (ที่ยืนยันกับหน้าทางการ: สัญญาสูงสุด 5 minis / 50 micros, วันเทรด 17:00–15:10 CT, consistency 55%, อนุญาตระบบอัตโนมัติ ส่วนเป้ากำไร $3,000 และ MLL $2,000 มาจากเว็บสรุปกฎ)

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `EXAM` | — | ใส่ `1` เพื่อเปิดโหมดสอบ |
| `START_BALANCE` | `50000` | ขนาดบัญชี |
| `EXAM_TARGET` | `3000` | เป้ากำไร |
| `EXAM_MLL` | `2000` | Maximum Loss Limit: เส้นเริ่มที่ ยอดเริ่ม − MLL เลื่อนขึ้นตามยอดเงิน **สิ้นวัน** สูงสุด และไม่เกินยอดเริ่ม (ล็อก) ยอด+กำไรขาดทุนที่ยังเปิดอยู่ แตะเส้น = ไม่ผ่าน (ตั้ง `EXAM_MLL_EQUITY=0` ให้ดูเฉพาะยอดที่ปิดแล้ว) |
| `EXAM_DLL` | `0` (ปิด) | ขาดทุนรายวัน (ตัวเลือกตอนสมัคร) ถึงเพดาน = ปิดทุกไม้และหยุดเปิดใหม่ถึงวันเทรดถัดไป บัญชียังอยู่ **ใส่ตามแผนที่คุณซื้อ** |
| `EXAM_CONSISTENCY` | `55` | วันที่ดีที่สุดต้องไม่เกิน % ของกำไรรวม ไม่งั้นต้องมีกำไรรวม = วันที่ดีที่สุด ÷ เกณฑ์ |
| `EXAM_MIN_DAYS` | `2` | จำนวนวันเทรดขั้นต่ำ (วันที่มีไม้ปิด) |
| `EXAM_CAP` | `50` | สัญญา micro สูงสุดรวมทุกสินทรัพย์ (10 micros = 1 mini) |
| `EXAM_RISK_PCT` | `0.5` | เสี่ยงต่อไม้ไม่เกิน % ของยอดเริ่ม (ลดขนาดให้อัตโนมัติ ถ้าสัญญาเดียวยังเสี่ยงเกินจะปฏิเสธ) |
| `EXAM_COMMISSION_RT` | `0` | ค่าคอมต่อสัญญา ไป-กลับ (ดอลลาร์) **ใส่ตามค่าจริงของคุณ** |
| `EXAM_FLAT_NY` / `EXAM_OPEN_NY` | `16:05` / `18:00` | ปิดทุกไม้และห้ามเปิดใหม่ช่วงนี้ (เวลานิวยอร์ก; Topstep ตัดวัน 16:10 NY) |
| `EXAM_CONFIG` | — | JSON ทับค่าข้างบนทั้งหมดได้ |

- สินทรัพย์ที่ใช้ได้ในโหมดสอบ: `US100`(MNQ) `US500`(MES) `US30`(MYM) `XAUUSD`(MGC) `XAGUSD`(SIL) `EURUSD`(M6E) `GBPUSD`(M6B) `AUDUSD`(M6A) — `USDJPY`/`USDCAD` ถูกข้าม (ราคาตรงข้ามกับสัญญา) มูลค่าต่อจุดและสเปรด ≈ 1 tick ใส่ให้แล้ว ปรับได้ด้วย `MULT_<คู่>`, `SPREAD_<คู่>` และ **ตรวจสัญญาที่แผนของคุณอนุญาต**
- ขนาดไม้เป็นสัญญาเต็ม (1 สัญญา = volume 100) ขั้นต่ำ 1 สัญญา
- ฝั่งเซิร์ฟเวอร์ปฏิเสธคำสั่งใหม่เมื่อ: ไม่มี SL, เสี่ยงเกินต่อไม้, เกินจำนวนสัญญา, นอกเวลาเทรด, ขาดทุนรายวันถึงเพดาน, หรือบัญชีสอบจบแล้ว (ข้อความ error ขึ้นต้น `EXAM_...` ESP32 จะขึ้นว่าส่งคำสั่งไม่สำเร็จ)
- ปิดทุกไม้อัตโนมัติเมื่อ: ถึงเวลา 16:05 NY, ขาดทุนรายวันถึงเพดาน, หรือยอดชนเส้น MLL
- ผ่านเมื่อ: กำไรปิดแล้ว ≥ เป้า, consistency ผ่าน, วันเทรด ≥ ขั้นต่ำ และไม่มีไม้เปิดค้าง จากนั้นหยุดเทรด
- ดู: Dashboard การ์ด "โหมดสอบ", `GET /api/exam`, คำสั่ง LINE "สถานะ" (มีบรรทัด 🎓) และ LINE จะแจ้งตอนไม่ผ่าน / ผ่าน / ขาดทุนรายวันถึงเพดาน
- `POST /api/reset` เริ่มการสอบรอบใหม่ (ล้างไม้และสถานะ)
- **ข้อจำกัดของ paper:** ราคาเข้า/ออกอิงแท่ง M5 ที่ปิดแล้วจาก Yahoo (อาจดีเลย์) ไม่มี slippage จริง และเมื่อแท่งเดียวชนทั้ง SL และ TP ถือว่า SL โดนก่อน ผลจึงเป็นการประมาณ ไม่ใช่การรับรองว่าจะผ่านสอบจริง ส่วนการเทรดจริงต้องผ่านแพลตฟอร์มของ Topstep เอง (ระบบนี้ไม่ได้ส่งคำสั่งเข้าบัญชีสอบ)
- ESP32 ต่อกับเซิร์ฟเวอร์ได้ทีละตัว (`CLOUD_URL`) ถ้าจะให้บอร์ดเทรดบัญชีสอบ ให้เปลี่ยน `CLOUD_URL` และ API key เป็นของเซอร์วิสสอบ
